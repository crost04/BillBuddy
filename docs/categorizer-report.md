## 3. Shops the model has never seen

In the comparison above, the same shop can appear in training and test data – realistic, because people shop at the same places again and again. To see how well the model generalizes, here the test data only contains shops that are missing from the training data (grouped cross-validation by shop):

| Model | Accuracy | Macro F1 |
|---|---|---|
| Text only (chosen) | 30.1 % | 20.0 % |
| Text + amount | 31.1 % | 19.3 % |

Unknown shops are much harder: the model can only use similar spellings ("Kletterwald" ~ "Kletterhalle"). The amount does not help here either. This is why learning from the user's own categories matters, and why the app makes no suggestion when it is unsure.

## 5. Confidence threshold

The app only makes a suggestion if the model's probability reaches a threshold. A higher threshold means fewer but more reliable suggestions. Known shops: as in section 2; unseen shops: as in section 3.

| Threshold | Known shops: with suggestion | Known shops: correct | Unseen shops: with suggestion | Unseen shops: correct |
|---|---|---|---|---|
| 0.0 | 100.0 % | 99.0 % | 100.0 % | 30.1 % |

| 0.4 | 99.4 % | 99.7 % | 37.9 % | 59.0 % |
| 0.5 | 99.0 % | 99.8 % | 26.2 % | 65.0 % |

Chosen: 0.7. For known shops it costs almost nothing, for unseen shops it clearly reduces wrong suggestions – and a wrong suggestion is worse than none, because the user has to notice and fix it.
