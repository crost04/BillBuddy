# Recurring-cost detection – evaluation report

Generated by `python -m billbuddy.ml.recurring.evaluate` on 2026-10-29 (sample data).

## 1. Data understanding

- 940 expenses → 191 different descriptions after cleaning ("Miete Oktober" and "MIETE November" become "miete").
- 10 of them are fixed costs, 181 are variable; 71 variable descriptions also appear at least 3 times (e.g. "rewe").

What separates them (median over the descriptions with at least 3 expenses):

|  | Median gap (days) | Std of the gaps (days) | Coefficient of variation of the amount |
|---|---|---|---|
| Fixed costs | 31 | 0.9 | 0.00 |
| Variable, frequent | 67 | 63.6 | 0.47 |

Fixed costs come every ~30 days on the same day with the same amount; frequent variable expenses come at irregular gaps with changing amounts.

## 2. Which rule does what? (ablation)

Each line adds one rule. Evaluated per description (series).

| Rules | Found (correct) | False alarms | Missed | Precision | Recall | F1 |
|---|---|---|---|---|---|---|
| Baseline: same description at least 3 times | 10 | 71 | 0 | 12.3 % | 100.0 % | 22.0 % |
| + gap about one month | 10 | 8 | 0 | 55.6 % | 100.0 % | 71.4 % |
| + regular gaps | 10 | 0 | 0 | 100.0 % | 100.0 % | 100.0 % |
| + similar amount = all rules (chosen) | 10 | 0 | 0 | 100.0 % | 100.0 % | 100.0 % |

- Counting alone flags every shop that is visited often.
- The monthly gap removes weekly shopping, the regularity removes shops visited "about monthly".
- The amount rule changes nothing on the sample data (already 100 %). It is kept for real cases the generator does not produce, e.g. a monthly online order with very different amounts (covered by a unit test).
- 100 % is optimistic: the sample data is tidier than real data. The real test is in daily use.
