# Receipt scan – evaluation report

Generated by `python -m billbuddy.ml.receipt_ocr.evaluate` on 2026-10-29: 400 synthetic receipts per noise level (random seed 42).

## 1. Data understanding and preparation

No real receipts are available yet (cold start). `synthetic.py` generates receipts in the layouts of German shop types (Rewe/Edeka/dm style, Lidl/Rossmann style, Aldi/Penny style, bakery) with quantity lines ("2 Stk x 0,59"), deposit, discounts, cash payment with change, VAT lines and two date formats. `ocr_noise` then simulates typical text-recognition mistakes: confused characters (0↔O, 1↔l, 5↔S, ","→"."), missing or extra spaces and lost lines. Noise level = probability per character.

Example (noise 5 %):

```
EDEKA Schmidt
Hauptstr. 5

   3 Stk x 0,96
```

## 3. Iteration: what the first evaluation changed

The first parser version broke down with noise: OCR split "SUMME" into "S UMME" or turned it into "SUMMC", so the total line was not found, and dates like "28.1O.2O26" were not repaired. Improvements: keywords are compared without spaces and with one wrong letter allowed; date-shaped text gets the same digit repair as amounts; shop names are compared with confusable characters unified.

| Noise | Total – first version | Total – now | Date – first version | Date – now |
|---|---|---|---|---|
| 1.0 % | 94.5 % | 98.8 % | 98.2 % | 98.2 % |
| 3.0 % | 84.8 % | 95.8 % | 91.5 % | 93.0 % |
| 5.0 % | 79.0 % | 94.5 % | 83.0 % | 86.8 % |
| 10.0 % | 62.5 % | 87.8 % | 69.8 % | 75.2 % |

- "Largest amount" fails whenever the customer paid cash: the money given is larger than the total.

## 5. Built-in plausibility check

If the items add up to the total, the scan is very likely complete. Share of receipts where this check passed **and** the total was right:

| Noise | Check passed | Check passed and total right |
|---|---|---|
| 0.0 % | 100.0 % | 100.0 % |
| 1.0 % | 96.0 % | 96.0 % |
| 3.0 % | 81.8 % | 81.8 % |
| 5.0 % | 74.5 % | 74.5 % |
| 10.0 % | 50.7 % | 50.7 % |

When the check passes, the total is practically always right – so the app can tell the user whether to double-check the scan.

## 6. Limits

- Synthetic receipts are tidier than real photos (folds, shadows, faded thermal paper, tilted shots). The real accuracy has to be measured with real receipts.
- Item names are kept as recognized; the evaluation matches items by amount.
